# Desktop Agent

Десктоп-приложение в духе Codex / Claude Desktop: агент работает с файлами и командами на вашем
компьютере, а всё, что что-то меняет, выполняется только после вашего «Разрешить».

Агент может работать двумя способами:

- **Встроенный чат.** Сейчас там демо-агент без интернета, он нужен, чтобы проверить приложение.
  Настоящий «мозг» (например, Notion AI через Agent API) подключается отдельным провайдером.
- **MCP-сервер.** Внешний агент (Hoplite, Custom Agent в Notion или любой другой MCP-клиент)
  подключается к приложению и получает те же инструменты с теми же подтверждениями.

## Запуск

Нужен Node.js 22.12+ (или 20.19+).

```bash
npm install
npm run dev
```

Установщик собирается командой `npm run build:win`, `npm run build:mac` или `npm run build:linux`,
результат появится в папке `dist/`.

## MCP-сервер: как подключить внешнего агента

1. В приложении выберите рабочую папку, откройте «MCP-сервер» внизу слева и включите переключатель.
   Сервер слушает только `127.0.0.1:7337`, порт можно поменять там же.
2. Установите cloudflared: `winget install --id Cloudflare.cloudflared` на Windows или
   `brew install cloudflared` на macOS.
3. Запустите туннель и не закрывайте окно терминала:
   ```bash
   cloudflared tunnel --url http://127.0.0.1:7337
   ```
   В выводе появится адрес вида `https://….trycloudflare.com`. Если туннель не подключается,
   добавьте `--protocol http2`.
4. В Hoplite: Settings → Project → MCP → Add server. URL — адрес из шага 3 с `/mcp` на конце,
   транспорт `http`, авторизация Bearer token — токен из приложения. Если Bearer token не
   предлагается, укажите в Advanced → Custom headers `{"Authorization": "Bearer <токен>"}`.
5. Для Custom Agent в Notion (тарифы Business и Enterprise) подходят тот же адрес и токен: в
   настройках агента Add connection → Custom MCP. Админ воркспейса должен разрешить свои
   MCP-серверы.

Адрес быстрого туннеля меняется при каждом запуске cloudflared, его нужно обновлять в настройках
агента. Для постоянного адреса подойдёт именованный туннель Cloudflare или статический домен ngrok.

Инструменты агента: `workspace_info`, `list_dir`, `read_file`, `write_file`, `run_command`,
`command_output`, `stop_command`.

Как это устроено:

- Каждая запись файла и команда появляется в разделе «Ждут вашего ответа». Если окно свёрнуто,
  приходит системное уведомление.
- На ответ есть 50 секунд: MCP-клиенты обычно обрывают запрос примерно через минуту. Если не
  ответить, агент получит отказ с объяснением.
- `run_command` ждёт результат до `wait_seconds` (по умолчанию 30 с). Более долгая команда
  продолжает работать в фоне, агент следит за ней через `command_output`, а вы можете остановить
  её кнопкой «Остановить». Фоновые команды живут не дольше часа и останавливаются при выключении
  сервера или выходе из приложения.
- Все ответы сервера — обычный JSON, без SSE: быстрые туннели Cloudflare SSE не поддерживают.
  Работают клиенты и новой спецификации MCP (2026-07-28), и прошлых версий 2025 года.
- Все действия агента сохраняются в журнале.

## Безопасность

- Пути за пределами рабочей папки, в том числе через симлинки, отклоняются файловыми
  инструментами. Команда в терминале может обратиться к чему угодно, что доступно вашему
  пользователю, поэтому каждую команду нужно подтвердить.
- Чтение файлов и папок выполняется сразу, запись файлов и любые команды — только после
  подтверждения.
- Явно разрушительные команды (`rm -rf /`, `format C:`, `mkfs`, `shutdown` и т. п.) блокируются без
  вопроса. Это грубая страховка, главная защита — подтверждение.
- MCP-сервер без токена отвечает `401`. С токеном можно читать файлы рабочей папки без
  подтверждения, поэтому не публикуйте его. Если токен утёк, нажмите «Новый», а когда сервер не
  нужен, выключайте его.

## Структура

```
src/
  main/        процесс Electron: окно, IPC, хранение чатов и журнала
    agent/     протокол, цикл агента, провайдеры («мозги») встроенного чата
    mcp/       MCP-сервер: HTTP и токен, инструменты, подтверждения
    tools/     инструменты, проверка путей, политика подтверждений, фоновые команды
  preload/     мост window.api между интерфейсом и main
  renderer/    интерфейс на React
  shared/      общие типы
```

## Как подключить другой «мозг» во встроенный чат

Провайдер реализует `AgentProvider` из `src/main/agent/providers/types.ts`: создаёт сессию, принимает
сообщение и возвращает ответ агента текстом. Пример — `demo.ts`. Новый провайдер добавляется в список
в `providers/index.ts` и появляется в выпадающем списке «Агент».
